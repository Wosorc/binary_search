## 2. Постановка задачи

Пользователь с клавиатуры вводит три целых числа:

- нижнюю границу диапазона (`left`);
- верхнюю границу диапазона (`right`);
- искомое («спрятанное») число (`hidden`).

Программа должна найти число в диапазоне [left; right] методом бинарного поиска, вывести ход поиска (номер шага, значения `left`, `right`, `mid` и результат сравнения), а по завершении — количество выполненных шагов и теоретический максимум шагов ⌈log₂(n + 1)⌉ для данного диапазона.

**Требования к программе:**

1. Проверка корректности ввода: при вводе не целого числа выводится сообщение об ошибке и значение запрашивается повторно.
2. Проверка границ: если `left > right`, программа выводит сообщение об ошибке и запрашивает все три числа заново. Равенство границ допускается (диапазон из одного числа).
3. Если искомое число не принадлежит диапазону, программа сообщает об этом и поиск не выполняет.
4. Поиск выполняется по границам (`left`, `right`, `mid`) без создания списка чисел и без встроенных функций поиска (`in`, `index`, `bisect`).
5. Алгоритм оформлен отдельной функцией `binary_search`, возвращающей количество шагов (или −1, если число не найдено).

**Принцип работы алгоритма.** На каждом шаге вычисляется середина `mid = (left + right) // 2`:

- если `mid` равно искомому — поиск завершён;
- если `mid` меньше искомого — поиск продолжается справа: `left = mid + 1`;
- если `mid` больше искомого — поиск продолжается слева: `right = mid − 1`;
- шаги повторяются, пока `left ≤ right`.

Временная сложность — O(log n). Максимальное число шагов равно ⌈log₂(n + 1)⌉, что в Python вычисляется как `n.bit_length()`.

## 4. Листинг программы

```python
def input_num(name): # Защищённый ввод: повторяет запрос, пока не введено целое число.
    while True:
        try:
            return int(input(f"Введите {name}: "))
        except ValueError:
            print("Ошибка: необходимо ввести целое число!")


def binary_search(left, right, hidden): # Бинарный поиск hidden в [left; right]
    steps = 0

    while left <= right:
        steps += 1
        mid = (left + right) // 2 # середина текущего диапазона
        print(f"Шаг {steps}: left={left}, right={right}, mid={mid}", end=" -> ")

        if mid == hidden:
            print(f"{mid} = {hidden}, число найдено.")
            return steps
        elif mid < hidden:
            print(f"{mid} < {hidden}, ищем правее.")
            left = mid + 1 # отбрасываем левую половину вместе с mid
        else:
            print(f"{mid} > {hidden}, ищем левее.")
            right = mid - 1 # отбрасываем правую половину вместе с mid

    return -1 # диапазон исчерпан, числа нет


def start_program(): # Ввод и проверка данных, запуск поиска, вывод итога.
    while True:
        left = input_num("число начала сектора")
        right = input_num("число конца сектора")
        hidden = input_num("спрятанное число")

        if left > right:
            print("Неверно введённый сектор!")
        elif not (left <= hidden and hidden <= right):
            print("Спрятанное число вне диапазона!")
        else:
            break

    count = right - left + 1 # количество чисел в диапазоне
    max_steps = count.bit_length() # равно ceil(log2(count + 1))

    steps = binary_search(left, right, hidden)

    print(f"Число {hidden} найдено за {steps} шагов.")
    print(f"Теоретический максимум для диапазона из {count} чисел: {max_steps} шагов.")


if __name__ == "__main__":
    start_program()
```

## 6. Ответы на контрольные вопросы

**1. Почему бинарный поиск применим только к упорядоченным данным?**

На каждом шаге алгоритм сравнивает искомое значение со средним элементом и по результату отбрасывает половину области поиска. Это возможно только если известно, что все элементы слева от середины не больше неё, а справа — не меньше. В неупорядоченных данных результат сравнения не говорит, в какой половине находится искомое, и искомое значение может быть неверно отброшено.

**2. Какова временная сложность бинарного и линейного поиска? Откуда берётся log₂ n?**

Линейный поиск — O(n), бинарный — O(log n). Каждый шаг уменьшает область поиска примерно вдвое: n → n/2 → n/4 → … Поиск закончится, когда останется один элемент, то есть после k шагов, где n / 2ᵏ ≈ 1. Отсюда k ≈ log₂ n.

**3. Сколько шагов в худшем случае потребуется для диапазона из 1 000 000 чисел? А из 1 000 000 000?**

Максимум шагов равен ⌈log₂(n + 1)⌉. Для 1 000 000 чисел это 20 шагов (2²⁰ = 1 048 576 > 1 000 001). Для 1 000 000 000 чисел — 30 шагов (2³⁰ = 1 073 741 824 > 1 000 000 001).

**4. Что произойдёт, если в цикле использовать условие `left < right` вместо `left ≤ right`?**

Когда границы сходятся (`left == right`), остаётся один непроверенный элемент, но цикл завершится, не сравнив его с искомым. В результате искомое число, оказавшееся последним кандидатом, не будет найдено. Например, в диапазоне из одного числа (5; 5; 5) цикл вообще не выполнится.

**5. Почему при сдвиге границ используются `mid + 1` и `mid − 1`, а не просто `mid`?**

Элемент `mid` уже проверен и не равен искомому, поэтому его можно исключить из области поиска. Если присваивать `left = mid`, то при `right = left + 1` значение `mid` совпадёт с `left`, границы перестанут меняться, и цикл станет бесконечным.

**6. Какие символы ГОСТ 19.701-90 используются для обозначения ввода/вывода, условия и цикла?**

Ввод и вывод — параллелограмм («данные»). Условие (ветвление) — ромб («решение»). Цикл — шестиугольник («подготовка»), либо пара символов «граница цикла». Также применяются терминатор (начало и конец) и прямоугольник («процесс»).

**7. В чём преимущества и недостатки рекурсивной реализации по сравнению с итеративной?**

Преимущества рекурсии: код короче и ближе к математическому определению алгоритма («задача делится пополам»). Недостатки: каждый вызов занимает память в стеке (глубина около log₂ n), есть накладные расходы на вызовы, а в Python действует ограничение глубины рекурсии. Итеративная версия использует O(1) памяти и работает быстрее, поэтому на практике предпочтительнее.
